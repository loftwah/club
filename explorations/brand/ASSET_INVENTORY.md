# Brand Asset Inventory & Assessment

> **Date:** 2026-08-23
> **Status:** Phase 2 · decision package
> **Generated by:** previous session (2026-08-22/23), curated by current session

This file is the canonical inventory of every visual asset that exists in
`explorations/brand/assets/` and `/public/explorations/brand/assets/`. Every
asset is assessed for visual quality, AI-typography reliability, and intended
use. The goal is honest documentation: weak assets are marked weak, not
hidden, and any asset that is shipped must be production-ready.

The file path `explorations/brand/assets/{direction}/{slot}.jpg` and
`public/explorations/brand/assets/{direction}/{slot}.jpg` are duplicated so
the Astro static site can serve them at the URL
`/explorations/brand/assets/{direction}/{slot}.jpg`. The
`public/explorations/brand/seals/*.svg` files are the **production-ready
SVG seals** that replace the AI-typography in the JPG reference seals.

---

## 1. Slot schema

Each direction has 8 visual slots:

| Slot           | Use                                  | Notes                                |
| -------------- | ------------------------------------ | ------------------------------------ |
| `hero_001`     | Hero / OG fallback / homepage visual | Wide photograph on warm surface      |
| `seal_001`     | Society seal concept                 | AI-typography risk; SVG replaces it  |
| `card_001`     | Membership card mockup               | AI-typography on member number area  |
| `invite_001`   | Event invitation mockup              | AI-typography on the date heading    |
| `cancel_001`   | Cancellation notice mockup           | Lower typography risk; less text     |
| `og_001`       | OG / social share 1200×630           | Wide composition, single seal        |
| `archive_001`  | Fictional Society record (archival)  | Aged-paper aesthetic, fictional text |
| `artefact_001` | Medallion / pin / physical object    | Material study; minimal typography   |

`001` is the first candidate per slot. The system is open to `002`, `003`,
etc. when re-rolling is useful. None of the existing assets are
production-final; this is a **concept gallery**.

**Direction B assessment**

This is the **most visually distinctive** of the three directions. The
oxblood + brass + walnut combination is unique to the brief and survives
re-rolling. The main watch-items:

- "B" and "C" are visually similar at thumbnail size (both warm, both
  paper-on-wood). The differentiator is oxblood vs hand-drawn monogram.
  A direction-B user looking at a thumbnail of a direction-C image may
  mistake them. This is acceptable in a decision gallery; the copy and
  palette are the differentiators.
- A real produced direction B at scale will need real foil-stamp and
  real engraved metal for the artefacts. The JPGs are visual _reference_,
  not production spec.

**Direction C assessment**

The visual register is _cohesive_ — every asset in the direction reads
the same. Direction A and B each have a single image that is stronger
than the others in their direction; C is consistently strong. The risk
is that C is the _softest_ direction in character and may be mistaken
for a small bookshop, a literary quarterly, or a stationery brand
rather than a paid social club.

## 6. SVG production seals (canonical, AI-typography-free)

These are the production seals and **replace the `seal_001.jpg` references
for any actual production use**:

| Direction | File                                                      | Format | Size            |
| --------- | --------------------------------------------------------- | ------ | --------------- |
| A         | `public/explorations/brand/seals/seal-a-modernist.svg`    | SVG    | 240×240 viewBox |
| B         | `public/explorations/brand/seals/seal-b-old-world.svg`    | SVG    | 240×240 viewBox |
| C         | `public/explorations/brand/seals/seal-c-quiet-modern.svg` | SVG    | 240×240 viewBox |

All three use `currentColor` so they pick up the surrounding palette
token and are usable on light cream or dark ink backgrounds. None depend
on a web font; arc text uses `ui-monospace` / `Cormorant Garamond` /
`IBM Plex Mono` fallbacks so the seal still reads correctly if the
selected face is unavailable.

The seal files are **the only assets a Phase 3 build can use without
re-doing the typography work**.
